# 0.14 Hardening Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Consolidate the accumulated LOW-severity backlog (#154) and 0.13 deferreds into a 0.14.0 release: reorganize e2e/examples for readability, close the client-correctness gaps, add two small APIs (timezone write, batched CardDAV multiget with reconciliation).

**Architecture:** 6 packages in 3 waves — H6 (e2e/examples reorg) ∥ H5 (docs/types) first; H1 (multiget engine) ∥ H3 (SabreDAV scheduling fixture) second; H2 (client correctness) ∥ H4 (timezone write) third. Each package: worktree + implementer subagent → review → gates → PR → CI 14/14 → squash merge.

**Tech Stack:** Rust (hyper 1.x, tokio, quick-xml), Docker fixtures (SabreDAV/Radicale/Nextcloud), cargo nextest, GitHub Actions.

## Global Constraints

- Spec: `docs/superpowers/specs/2026-09-05-roadmap-014-design.md` (approved).
- Gates before every PR: `cargo fmt --all`; `CARGO_TARGET_DIR=target cargo clippy --all-targets --all-features -- -D warnings`; `CARGO_TARGET_DIR=target cargo nextest run --all-features --locked --test unit_tests`; `CARGO_TARGET_DIR=target cargo test --doc --all-features`; `cargo test --all-features --locked --no-run`. Always set `CARGO_TARGET_DIR=target`.
- CI must be 14/14 (verify explicitly with `gh pr checks`) before each merge.
- Duplication gate ≤3%: CalDAV/CardDAV must share via `webdav/`/`common/`, never copy-paste.
- Sonar coverage ≥80% on new code (e2e-only paths exempt, documented in PR).
- Provider A is never named in repo artifacts; no production URLs.
- No uids/tokens interpolated into log lines or assertion messages (CodeQL).
- `#[non_exhaustive]` on new public structs/enums; wildcard arms when matching.
- Docs in sync (README, AGENTS.md, doc comments, CHANGELOG) — stale docs are bugs.
- CI `[[test]]` target names are frozen: `unit_tests`, `e2e_tests`, `e2e_radicale`, `e2e_nextcloud`, `e2e_provider_a_smoke`.
- English docs; no emoji; no TODO/FIXME comments left in code.
- Fix rounds go through the implementer subagent, never the controller.
- Release 0.14.0 only on explicit user go.

  /// Set or remove a calendar's `calendar-timezone` property (RFC 4791 §5.2.2).
  ///
  /// - `Some(vtimezone)` sets the property; the VTIMEZONE iCalendar object is
  ///   sent verbatim (XML-escaped) — the crate never parses iCalendar.
  /// - `None` sends a `<D:remove>` for the property.
  ///
  /// The server's per-property status inside the 207 multistatus decides the
  /// result: a non-success propstat for `calendar-timezone` maps to
  /// `Error::UnexpectedStatus` with `Operation::ProppatchCalendarTimezone`
  /// (servers commonly accept the request but reject the property — Radicale,
  /// for example, does not implement it).
  ///
  /// ```no_run
  /// # use fast_dav_rs::{CalDavClient, Result};
  /// # async fn demo(client: &CalDavClient) -> Result<()> {
  /// let vtz = "BEGIN:VCALENDAR\r\nVERSION:2.0\r\n...END:VCALENDAR";
  /// client.set_calendar_timezone("/calendars/me/personal/", Some(vtz)).await?;
  /// client.set_calendar_timezone("/calendars/me/personal/", None).await?;
  /// # Ok(())
  /// # }
  /// ```
  pub async fn set_calendar_timezone(
      &self,
      calendar_path: &str,
      vtimezone: Option<&str>,
  ) -> Result<()> {
      const SET_TPL: &str = concat!(
          "<?xml version=\"1.0\" encoding=\"utf-8\"?>",
          "<D:propertyupdate xmlns:D=\"DAV:\" xmlns:C=\"urn:ietf:params:xml:ns:caldav\">",
          "<D:set><D:prop><C:calendar-timezone>{}</C:calendar-timezone></D:prop></D:set>",
          "</D:propertyupdate>"
      );
      const REMOVE_BODY: &str = concat!(
          "<?xml version=\"1.0\" encoding=\"utf-8\"?>",
          "<D:propertyupdate xmlns:D=\"DAV:\" xmlns:C=\"urn:ietf:params:xml:ns:caldav\">",
          "<D:remove><D:prop><C:calendar-timezone/></D:prop></D:remove>",
          "</D:propertyupdate>"
      );
      let body = match vtimezone {
          Some(vtz) if vtz.trim().is_empty() => {
              return Err(Error::InvalidInput(
                  "set_calendar_timezone: an empty VTIMEZONE cannot be set; \
                   pass None to remove the property"
                      .to_owned(),
              ));
          }
          Some(vtz) => format!(SET_TPL, xml_escape(vtz)),
          None => REMOVE_BODY.to_owned(),
      };
      let resp = self.webdav.proppatch(calendar_path, &body).await?;
      let status = resp.status();
      if !status.is_success() {
          return Err(Error::unexpected_status(
              Operation::ProppatchCalendarTimezone,
              status,
          ));
      }
      // 207: inspect the propstat entry for C:calendar-timezone.
      let ms = parse_multistatus_bytes(&resp.into_body())?;
      for item in &ms.items {
          for propstat in &item.propstats {
              if propstat
                  .props
                  .iter()
                  .any(|p| p.name.eq_ignore_ascii_case("calendar-timezone"))
                  && !(propstat.status.starts_with('2'))
              {
                  return Err(Error::unexpected_status(
                      Operation::ProppatchCalendarTimezone,
                      StatusCode::from_u16(
                          propstat.status.split(' ').nth(1).and_then(|s| s.parse().ok()).unwrap_or(500),
                      )
                      .unwrap_or(StatusCode::INTERNAL_SERVER_ERROR),
                  ));
              }
          }
      }
      Ok(())
  }
  ```
  IMPORTANT: verify the actual shapes at implementation time — `PropStat` field names (`status`, `props`, prop `name`), the `escape_xml` helper's real path/visibility (`src/webdav/xml.rs`), and whether `Error::unexpected_status(op, status)` is the correct constructor signature (check `src/error.rs`). `parse_multistatus_bytes` is used by `calendar_timezone`'s read path — mirror its import style.
